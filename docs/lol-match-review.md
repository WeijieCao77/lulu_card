# LoL 比赛模拟整改（2026-09-21）

## 问题与规则依据
卡牌天梯、好友房、杯赛仍调用 VAL 回合模拟，单图 13 分获胜，战报累计 K/D 混作单局展示。
Riot 的 [玩法说明](https://www.leagueoflegends.com/en-sg/how-to-play/)说明：双方各五人，推掉敌方基地水晶获胜。击杀并非胜负判定；只需打通一路及基地防线，不必推掉所有 11 座塔。

## 施工与审查
实际调用 DeepSeek V4 Pro 两轮模拟器实现，以及战报组件实现；主代理审查后修正并集成。
被拒绝的问题：全局随机种子、固定 50 分钟、强度没有被使用、同一资源两边重复取得、同一团战死人继续参战、首杀记录漏算、单局与累计混淆。

- 卡牌对战统一进入 `lolMatch.ts`，职业经理旧引擎保留。
- 以分钟推进交战、经济、推塔、小龙和大龙，推进结束比赛；BO1/3/5 按局数取胜。
- 保留已结算的旧战报，标明“旧版战报”；不改账号库存、段位或已发奖励。
- 阵容分继续包含升级、教练、默契和错位影响。移除旧回合模拟器测得的胜率表，避免用不适用的数字误导玩家。
- 每次击杀对应一名敌方选手死亡；助攻去重且不含击杀者；团战死亡者不再出手。
- 资源使用全局冷却，双方不能在同一时刻各拿同一条龙。
- 战报默认单局 K/D/A、KDA、补刀、时长和资源，另设系列赛合计；全服杯归档保留单局数据，翻转视角同步翻转胜方及资源。
- 手机优先显示比分和数据，阵容、关键事件可展开，表格在自身容器内滚动。

这是轻量卡牌游戏模拟，击杀频率、经济和时长是设计参数，不声称复现真实比赛或官方统计。50 分钟为模拟安全上界，以决胜推进收束；无枪械经济、攻守换边或 13 分判胜。

## 验收
`check_lol_match.ts`：600 个 BO 系列赛，共 1,542 局；平均 30.24 分钟、双方合计 32.15 次击杀；双方等强时 A 方赢 280/600 场，14 点有效实力领先时赢 175/200 个单局。500 个单局出现击杀落后方获胜。
验证种子重放、输入不变、系列赛提前结束、击杀/死亡守恒、助攻上限、金币分配守恒、一血唯一、资源数量上限、事件时间和卡牌单局映射。此抽样不是胜率保证。
六赛区天梯及完整杯赛、杯赛报名冻结/升级/市场托管/客户端注入/旧赛恢复 API 回归通过。
战报 320×568、390×844、667×320 下检查过；320 宽度无页面级溢出，数据表可独立滚动。

旧测试 `check_coach_identity.ts` 仍断言 WOL/NOVA 的 VAL 阵容；`check_coach_values.ts` 的三类阵容共 114 位教练属性/升级检查通过，但随后失败于旧 VLR 阵容哈希固定值。这两项旧固定数据断言不作为 LoL 发布检查；没有改运行时代码去迁就旧数据。
