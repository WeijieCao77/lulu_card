# 内测性能检查 · 2026-09-21

结论：本地普通浏览场景下，100/200 个模拟在线用户没有出现请求错误。集中比赛明显排队；同一网络下集中登录会触发现有 IP 限流。**尚未完成 Railway 同规格容量验收、真实手机测试或长期内存稳定性测试，不承诺百人同时比赛流畅。**

## 环境与范围

- Windows ARM64，Node 24.14.0，本机 PostgreSQL 18（Windows x64 仿真运行），localhost HTTP；部署使用 Node 22，硬件、网络和运行时均不同。
- `scripts/pg/check_mixed_load.mjs` 使用实际 API 处理器及实际比赛计算，运行在测试 HTTP 容器中，并非完整生产 server.js / Railway 代理。
- 每次创建独立 UTF-8 临时数据库，结束后删除自己的测试库；未向线上或试玩数据库灌数据。
- 交互/后台/统计连接池分别 4/1/2。普通场景每人请求间隔约 1–3 秒，使用独立限流桶。混合后台工作含杯赛 895 场比赛、市场结算及统计数据。
- RSS 包含压测发请求的代码、应用和比赛 Worker，**不包含 PostgreSQL 进程，也不是浏览器内存**。峰值采样间隔 250ms。
- 普通写入使用签到重放，不能替代高频开包、交易、奖励一致性与全功能压测。比赛突发场景单独测试真实天梯计算。

## 结果

| 场景 | 请求结果 | 关键 p95 | 应用峰值 RSS | 限制 |
| --- | --- | --- | --- | --- |
| 100 人普通操作，发请求 60 秒 | 3,022 次 200，无错误 | 加载 5.3ms / 市场 17.9ms / 操作 5.1ms | 484MB | 含后台任务共 63.07 秒；不同网络限流桶 |
| 200 人普通操作，发请求 30 秒 | 3,074 次 200，无错误 | 加载 4.1ms / 市场 15.3ms / 操作 6.6ms | 495MB | 含后台任务共 48.52 秒；时长不同，不能据此声称扩容更快 |
| 100 人无间隔突发，含真实天梯 | 5,624 次 200；561 场比赛完成 | 天梯 3,618.4ms / 市场 336.4ms / 加载 128.9ms | 988MB | 为测饱和关闭测试限流；发请求 15 秒，排空及后台共 62.3 秒 |
| 同网络 100 账号同时加载 | 40 次 200、60 次 429 | 不作为延迟验收依据 | 172MB | 使用真实限流；无后台杯赛任务 |

突发比赛 Worker 最大等待 98，失败/拒绝均为 0；事件循环 p99 约 24ms。没有请求失败并不代表等待体验合格。普通场景结束时 RSS 分别约 475/372MB，突发结束约 413MB，短测试不足以证明内存无泄漏。

## 浏览器改动与验证

- 名人堂每页 12 张，收藏每页 48 张；切换筛选重置页码，移除收藏原先最多展示 240 张的截断。卡面图片使用异步解码。
- 桌面浏览器实测名人堂列表仅 12 张卡、包含主视觉共 13 张照片，翻页正常；收藏缺卡视图每页 48 张，1/18 到 2/18 翻页正常。
- 390×844 窗口下名人堂与收藏没有水平溢出，账号页不再展示手机绑定入口。
- 当时名人堂 13 张已加载图片按原始尺寸 × 4 字节估算约 35MB 解码量。此数字不是实测 JS 堆、进程 RSS 或 GPU 占用，不应相互替代。
- 未完成真机、连续开包长时间测试、后台恢复、GPU/JS 堆快照或弱网测试。不能将桌面窄窗口当作真机验收。

## 正式发布前待办

1. 同 Wi-Fi、校园网、运营商 NAT 下的账号加载目前受 IP 40 次/分钟限制，100 人同时登录会误伤。需要兼顾账号防枚举和防脚本，设计并验证账号与网络分层限流，不能简单关闭限流。
2. 在与 Railway 一致的 CPU、内存、Node 版本和数据库配置下，测试 100/200/300 人普通与集中写入场景；检查比赛队列、超时、拒绝提示和资源上限。1GB 的应用限制在当前突发数据下缺乏余量，不能据此直接定生产规格。
3. 至少 30 分钟持续压测及真实 Android/iPhone 内存、帧率、图片缓存、连续开包和后台恢复测试。
4. 记录完整服务器、代理和数据库指标及网络延迟；验证集中开包/竞价/奖励领取的资金一致性，测试共享网络防刷与合法玩家体验。

完整发布门槛见 [正式上线检查](production-release-checklist.md)。DeepSeek 参与前后端性能审查；以上结论以实际本地测试为准。

## 复测

脚本需要仅用于测试的 localhost PostgreSQL 管理连接 `PG_TEST_URL`，有创建临时数据库权限；禁止指向生产。通过 `PG_LOAD_WAVES=100`（可用逗号列出多轮人数）/ `PG_LOAD_SECONDS` / `PG_LOAD_THINK_MS` / `PG_LOAD_LIMITS` / `PG_LOAD_SHARED_IP` 选择场景，设置 `PG_LOAD_OUT` 为输出 JSON 路径后运行 `node scripts/pg/check_mixed_load.mjs`。使用 `PG_LOAD_CASE=shared-login` 单测共享网络、`PG_LOAD_ACTION=ladder` 测真实比赛；不加节奏、关闭测试限流的结果只能代表饱和测试。
