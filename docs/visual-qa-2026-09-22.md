## 源码审计与撤销的误报

第一轮 DeepSeek 输出在 `.local-data/deepseek-visual-audit-round1.json`，第二轮在 `deepseek-visual-audit-round2.json`。审查没有照单应用其推测。

- 图鉴 `.dossier-card-face` 的 `flex-basis:60px` 不等于实际宽度：min-content 将其扩展到 96px。真实 DOM 排除图片侵入文字，不做多余修改。
- PackStage 的候选布局先筛掉 `horizontalFit < 72`，再选择适配项或滚动布局；不能因某个 fallback 没有另加 clamp 就断言目标视口出现接近 0 的卡宽。相关误报撤销。
- 概率表格需要横向滑动不等于页面溢出；上述真实测量已排除该误报。
- 页脚可能过高、横屏卡桌被挤压目前仍需对应状态的实际尺寸证据，不能仅凭 CSS 风险报告为已发现缺陷。
- 字体使用现有系统字体回退栈，当前入口没有外部字体下载依赖。保持品牌字号与字体，不凭主观猜测改全局排版。

## 已修复与复验

### 挑战搜索候选不再被入口遮挡

DeepSeek 生成 Challenge 的表单聚焦/候选状态与小屏 CSS。Codex 审核发现初稿的 effect 无条件设置属性，会造成没有候选时也隐藏入口，已退回模型返修后再应用。最终状态为 `!state.done && (searchFocused || matches.length > 0)`；仅在 ≤720px 隐藏概率/日志浮动入口，使用 `display:none` 同时避免不可见入口占据 Tab 顺序。候选仍在时失焦不闪回，卸载清理状态；弹窗、遮罩和关闭按钮不隐藏。

主线程复验 320×568：输入 faker 后两个入口 display none，截图候选完整无遮挡；清空并失焦后入口恢复，概率弹窗正常打开且关闭可见；有候选时直接离开挑战回抽卡，状态已清理且入口恢复。1440×900 输入 faker 时状态虽 active，入口仍 display flex，桌面不受隐藏规则影响。

### 翻牌后透明粒子不再撑出横滚条

667×375 原卡桌 `clientWidth=609, scrollWidth=636`。实际只有两个粒子超出卡桌，opacity=0，x=655.358…660.358，而卡桌右边界为 643.333。原动画 `fill-mode:both` 将透明粒子保留在远端；DeepSeek 最小补丁改为基态 opacity 0、`animation-fill-mode:backwards`，动画结束恢复无位移。没有使用 overflow-x:hidden 裁掉卡牌内容。

复验同视口 `clientWidth=scrollWidth=609`，超界子元素由 2 个变 0，横滚条消失。纵向 `scrollHeight=348/clientHeight=246` 保留，仍可滚动查看全部卡牌。页脚与卡桌未重叠。

### 姓名显示实体字符

浏览器发现 Levitate 真名显示 `Ha-Lim&amp;nbsp;&quot;Joseph&quot; Hong`。源码盘点同类 44 条，均为 world.json 的选手 realName；URL 的 `&amp;` 不纳入姓名处理。DeepSeek 实现 `displayText.ts` 纯文本有限实体解码，在卡牌 realName 构造入口统一应用，卡面、图鉴和姓名搜索共享处理结果。最多 3 轮有限替换，不解析 HTML、不使用 innerHTML，不修改 ID、评分、属性或来源 URL。未知实体保留，普通 Unicode 姓名保持原样。

`npx tsx scripts/check_display_text.ts` 已通过：Levitate 正确显示值为 `Ha-Lim "Joseph" Hong`；双重编码、重音字符、未知实体、空值及原始姓名残留检查均通过，所有基础卡 ID/rating 与源数据映射保持一致。Codex 修正了模型测试草稿中一个不存在的卡牌 ID，改为通过实际 IGN 查找。

主线程随后在真实浏览器图鉴复验 Levitate，真名已显示 `Ha-Lim "Joseph" Hong`，没有编码残留。
